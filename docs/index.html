Docker-first coordination for patient agents

Suzumio

Suzumio is a general multi-agent runtime designed around one strict rule: once an agent is working, do not interrupt it. Messages queue in a mailbox, turns run in Docker, and project state lives in SQLite.

What Suzumio Is

Suzumio is not a proof assistant harness, not an OpenCode wrapper, and not a chat UI. It is a runtime layer for coordinating multiple long-running agents across a project. It owns the durable project truth: configuration, agents, turns, messages, events, tool calls, artifacts, approvals, and observability.

The first implementation includes a Docker-first single-agent runner. The runner executes one turn, talks to Suzumio's ToolHost when it needs project tools, writes a result file, and exits. The scheduler then decides whether any other agent has unread inbound messages and should receive a new turn.

Non-preemptive

Running agents are never prompted again, nudged, or interrupted by the scheduler. New messages wait until the current turn finishes.

Mailbox-driven

An idle agent wakes only when it has unread inbound messages. If there is no inbound work, it stays quiet.

Docker-first

The backend launches isolated containers for turns. Suzumio does not try to make in-process execution the default path.

Tool-audited

Project tools are served by Suzumio, not by the runner. Calls are permissioned by agent config and recorded in SQLite.

Design Promise

Suzumio intentionally prefers quiet waiting over noisy orchestration. The runtime should not manufacture work, poll agents through prompts, or force a project manager to comment while workers are still running.

This is the main lesson imported from earlier multi-agent experiments: if the useful work is a long proof attempt, a long code edit, or a long review pass, the scheduler should preserve that uninterrupted context instead of constantly asking for status.
