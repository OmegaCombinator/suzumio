Operations

Run, inspect, and clean projects

Suzumio is designed to be transparent. Every important object has a CLI view and an HTTP view backed by the same SQLite store.

Environment

export SUZUMIO_ROOT=/data/suzumio-runtime

Set SUZUMIO_ROOT before running commands. Runtime state should not live inside the source repository.

Core Commands

CommandPurpose
suzumio config render file.yamlResolve imports and profiles, then print final config.
suzumio init file.yamlCreate project directories and SQLite state.
suzumio serveStart HTTP API, WebUI, ToolHost, SSE stream, and scheduler loop.
suzumio start projectMark project running and tick scheduler.
suzumio send project agent P1 "..."Send a user message and tick scheduler.
suzumio status [project]Show project and agent status.
suzumio turns projectShow recent turns.
suzumio events projectShow event timeline.
suzumio artifacts projectShow artifact registry.
suzumio stop projectDisable scheduling.
suzumio approve projectMark a submitted project completed.

Recommended Run Pattern

npm run build
docker build -t suzumio-runner:dev .

export SUZUMIO_ROOT=/data/suzumio-runtime
suzumio config render examples/demo.yaml
suzumio init examples/demo.yaml
suzumio serve --host 0.0.0.0 --port 39400

Then, from another terminal:

export SUZUMIO_ROOT=/data/suzumio-runtime
suzumio start demo
suzumio send demo pm P1 "Start the project."

Inspecting a Turn

A turn directory contains the exact runner input and output:

$SUZUMIO_ROOT/demo/turns/turn_.../
  input.json
  output.json

The input includes the rendered prompt, the agent identity, the controller URL, the runner config, and the tool definitions available to the model.

Cleaning Debug Containers

Early Suzumio keeps completed turn containers for debugging. Remove only Suzumio-owned containers:

docker ps -a --filter name=suzumio
docker rm <container-name>

Do not run broad Docker prune commands on shared machines. Suzumio should only clean containers it created.

Secrets

Use environment variables for API keys and local, untracked config for private gateway URLs.

export SUZUMIO_GATEWAY_API_KEY=...
suzumio serve --host 0.0.0.0 --port 39400

The runner backend passes configured provider key environment variables into containers when those variables exist in the host environment.

Deployment Notes

For a long-running server, use a process manager such as systemd, a container, or a supervised shell session. The first version does not include a production daemon wrapper.

For GitHub Pages documentation, the workflow uploads the static docs/ directory. To use a custom domain later, configure the domain in GitHub Pages settings and DNS. Add a CNAME file only when you are ready to make the custom domain authoritative.
