Configuration

One file or many files

Suzumio config is YAML with strict whole-field imports and explicit profile composition. You can keep a project in one file or split task text, prompts, agents, and backend settings across files.

Minimal Config

name: demo
task: |
  Demonstrate one non-preemptive turn.

backend:
  runner:
    mode: mock

agents:
  pm:
    role: project-manager
    prompt: |
      Coordinate the project and stay concise.
    tools:
      - messages.send

Import Rules

A scalar value whose whole value is @import(path) is replaced by the imported file.

task: @import(tasks/main.md)
agents:
  pm: @import(agents/pm.yaml)

If agents/pm.yaml contains:

role: project-manager
prompt: |
  Assign work, then wait quietly.
tools:
  - messages.send

then the resolved config contains:

agents:
  pm:
    role: project-manager
    prompt: |
      Assign work, then wait quietly.
    tools:
      - messages.send
RuleDetails
Whole-field only@import(path) replaces the entire field value. String interpolation is intentionally not supported.
Relative pathsPaths are resolved relative to the file containing the import.
Structured formats.yaml, .yml, and .json are parsed into objects.
Text formatsOther files are imported as text.
ReproducibilityHTTP and HTTPS imports are disabled.
SafetyRecursive imports are supported with circular import detection and depth limits.

Extends

Top-level extends composes profiles. Imports are resolved first, then objects are deep-merged. Later entries and the project file override earlier fields.

extends:
  - @import(profiles/base.yaml)
  - @import(profiles/acorn.yaml)

name: sqrt2-plus-sqrt3
task: @import(tasks/sqrt2-plus-sqrt3.md)

agents:
  worker:
    count: 3

Arrays are replaced, not concatenated. This makes resolved configs easier to debug because a later profile cannot silently append unexpected tools or agents.

Project Fields

FieldRequiredPurpose
nameYesProject id and runtime directory name.
taskYesDurable project task included in each turn prompt.
schedulerNoScheduler kind and options. Defaults to nonpreemptive-mailbox.
backendNoDocker runner image, controller URL, and runner mode/model settings.
agentsYesAgent roster. At least one agent is required.
channelsNoAllowed project channels. Unknown channels are rejected.
observabilityNoHTTP and WebUI defaults.

Backend and Runner

backend:
  kind: docker-chat
  image: suzumio-runner:dev
  controllerUrl: http://host.docker.internal:39400
  runner:
    mode: mock

Use mock for infrastructure tests. Use ai for model-backed turns.

AI Model Config

backend:
  runner:
    mode: ai
    model: main
    models:
      default: main
      providers:
        gateway:
          type: openai-compatible
          baseURL: https://your-gateway.example/v1
          apiKeyEnv: SUZUMIO_GATEWAY_API_KEY
      presets:
        main:
          provider: gateway
          model: gpt-5.5
          apiModel: gpt-5.5
          toolChoice: auto

Do not commit real API keys or private gateway URLs. Use local untracked config and environment variables.

Agent Config

agents:
  worker:
    role: worker
    count: 2
    prompt: @import(prompts/worker.md)
    model: main
    tools:
      - messages.send
      - artifacts.publish
      - artifacts.list

If count is greater than one, Suzumio expands the agent into worker-1, worker-2, and so on.

Render Before Running

suzumio config render examples/import-demo.yaml

The rendered config is the best debugging artifact. It shows exactly what Suzumio will validate and store.
