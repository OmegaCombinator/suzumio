HTTP API and ToolHost

The HTTP server exposes project observability, user control actions, SSE event streaming, and the container-facing ToolHost.

General

The server starts with:

suzumio serve --host 0.0.0.0 --port 39400

The current API is intentionally small and intended for local or trusted-network use. Authentication for user-facing API routes is not implemented in the first version. The container-facing tool route uses per-agent tokens.

Health

MethodPathResponse
GET/health{ "healthy": true }

Project Listing

MethodPathDescription
GET/api/projectsList projects under SUZUMIO_ROOT.
GET/api/projects/:projectProject summary with redacted agents, recent turns, and recent messages.

Project Objects

User Control Actions

MethodPathBodyDescription
POST/api/projects/:project/startEmptySet project status to running and tick scheduler.
POST/api/projects/:project/stopEmptySet project status to stopped.
POST/api/projects/:project/approveEmptySet project status to completed.
POST/api/projects/:project/request-changes{ "recipient": "pm", "body": "..." }Return project to running and send a user message.
POST/api/projects/:project/messages{ "recipient": "pm", "priority": "P1", "body": "..." }Create a user or custom-sender message and tick scheduler.

SSE Stream

The event stream sends SQLite events as Server-Sent Events.

GET /api/projects/:project/stream

Each event contains:

event: message.created
data: { ...event row... }

ToolHost

The Docker runner uses POST /tool to execute project tools. This route is not a public user API.

POST /tool
{
  "project": "demo",
  "agentId": "pm",
  "turnId": "turn_...",
  "token": "agent-private-token",
  "tool": "messages.send",
  "input": {
    "recipient": "user",
    "priority": "P1",
    "body": "Done."
  }
}

The ToolHost verifies that the token matches the agent and that the requested tool is in the agent allowlist. It records a tool_calls row before execution and updates it after success or failure.

Core Tool Inputs

messages.send

{
  "recipient": "worker",
  "channel": "#project",
  "priority": "P2",
  "body": "Markdown message"
}

Use either recipient or channel, not both.

artifacts.publish

{
  "path": "relative/path/in/workspace.txt",
  "name": "optional-name.txt",
  "description": "What this artifact contains"
}

artifacts.list

{}

completion.submit

{
  "report": "# Final Report\n\n..."
}

This writes final-report.md, marks the project submitted, and waits for user approval.

WebUI

The root path / serves the embedded WebUI. It calls the API routes above and refreshes periodically.
