Concepts

Turns, mailboxes, and quiet agents

Suzumio's behavior is intentionally simple. It starts agents only when they have inbound work, and it never interrupts an agent that is already running.

Project

A project is the top-level unit of coordination. It has one resolved config, one SQLite database, one task statement, one agent roster, one artifact registry, and one event stream.

The project status controls scheduling:

StatusMeaning
initializedCreated but not scheduled.
runningScheduler may start ready agents.
submittedFinal report was submitted and waits for user approval.
completedUser approved the result.
stoppedScheduling is disabled.
failedReserved for project-level failures.

Agent

An agent is a named participant with a role, prompt, model, tool allowlist, workspace, and private token. Suzumio stores agent state in SQLite and passes only the needed turn input into the container runner.

Agent states are deliberately small:

StateMeaning
quietThe agent is idle and has no unread inbound messages.
readyReserved for derived/UI state when inbound messages exist.
runningA Docker turn is active. The scheduler must not prompt this agent.
failedThe last turn failed or the backend reported an error.
stoppedThe agent is disabled.

Message

Messages are durable project records. They can be direct messages to one agent or channel messages to a configured project channel. A user is represented as a virtual sender named user.

{
  "sender": "user",
  "recipient": "pm",
  "priority": "P1",
  "body": "Start the project."
}

A message is consumed by an agent only when the scheduler starts a turn for that agent and marks the selected inbound messages as read for that turn.

Turn

A turn is one isolated agent execution. It has a prompt, an input file, an output file, a status, optional text, optional error, usage metadata, and a container name.

Turns are not chat messages. They are execution records. A turn may result in text, tool calls, published artifacts, sent messages, or a final submission.

Non-preemptive Mailbox Scheduler

The first scheduler is nonpreemptive-mailbox. Its rules are the heart of Suzumio:

  1. If an agent is running, do nothing to it.
  2. If a project is not running, do nothing.
  3. If an idle agent has no unread inbound messages, keep it quiet.
  4. If an idle agent has unread inbound messages, render exactly one turn prompt and start one Docker turn.
  5. New messages that arrive during a turn wait in the mailbox.
  6. There are no heartbeats, no automatic status prompts, and no scheduler-generated nudges.

ToolHost

The container runner does not own project tools. It calls Suzumio's HTTP ToolHost. The ToolHost checks the agent token, verifies the tool allowlist, records the tool call, executes the core tool, and records success or failure.

Artifact

An artifact is a file published from an agent workspace into the project artifact registry. Suzumio records its id, creator, turn id, name, path, SHA-256 hash, description, and timestamp.

Why Quiet Waiting Matters

In a long-running agent system, interruptions are expensive. A project manager that has already delegated work should not be prompted repeatedly to say it is waiting. A worker trying a long proof or code change should not be interrupted to report that it is still trying. Suzumio treats uninterrupted work as the default, not as an exception.
